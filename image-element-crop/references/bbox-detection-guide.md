# 目标元素 bbox 识别指引

本 skill 的识别与裁剪是**解耦**的两步：

1. **感知（本文档指导的部分）**：由 CodeBuddy 自身的多模态视觉理解直接读图，
   为每张图输出目标元素的边界框 `bbox`（相对坐标 0~1），产出 `bboxes.json`。
   不使用传统 OpenCV 阈值分割 / GrabCut / 背景差分等方法——这些方法在复杂背景、
   非最显著局部目标的场景下鲁棒性很差。
2. **计算（`scripts/crop_by_bbox.py` 负责的部分）**：根据 bbox + 目标尺寸 +
   padding 百分比 + fit 策略（`contain`/`cover`）做确定性的裁剪、缩放数学运算，
   不依赖任何模型推理。正式裁剪前可用 `scripts/render_bbox_preview.py` 查看 bbox、
   padding 和最终裁剪框的叠加预览。

> 识别 bbox 时**不需要**关心最终用的是 `contain` 还是 `cover`：始终按目标元素真实
> 外接矩形框选即可，两种策略的差异完全由下游几何计算处理（`contain` 保证完整保留，
> `cover` 允许裁边铺满画布），不应因为策略不同而调整框选范围。

## bboxes.json 格式

```json
[
  {"name": "商品A", "bbox": [0.12, 0.08, 0.91, 0.76]},
  {"name": "商品B", "bbox": null}
]
```

- `name` 与 `manifest.json` 中的 `name` 字段一一对应。
- `bbox` 为 `[x1, y1, x2, y2]`，四个值均为 0~1 的相对坐标：
  - `(x1, y1)` = 目标元素外接矩形的左上角
  - `(x2, y2)` = 目标元素外接矩形的右下角
  - 坐标系：图片左上角为 `(0,0)`，右下角为 `(1,1)`
- 完全无法识别到目标元素时，`bbox` 设为 `null`（不要瞎猜一个框）。

## 两种识别策略：按描述定位 vs 自动识别主体

每条 `manifest.json` 记录都带有 `description` 字段（可能为 `null`）。**识别前必须先看这个字段**，据此切换策略：

### 策略 A：`description` 非空 —— 按描述定位局部元素

此时目标**未必是**画面中最大、最居中、最显著的对象，而是画面里与描述文本匹配的**特定局部元素**。

典型场景（用户提供的真实案例）：一张多人合照里，目标是某个人头顶戴着的蓝色皇冠道具，而不是画面中的人物本身。

处理方法：
- 仔细阅读 `description`，在整张图中搜索与描述语义匹配的物体/局部区域，即使它只占画面很小一部分。
- 只框选描述所指的那个元素本身，不要把承载它的人/背景/整个场景都框进去。
- 若图中有多个相似元素（如两个人都戴了皇冠），优先选择更符合描述细节（颜色/位置/形态）的那一个；如果确实无法区分，选择最清晰/最完整可见的一个。
- 若描述所指元素在图中确实不存在或无法辨认，返回 `bbox: null`，不要强行框一个不相关的区域。

示例对比：
| description | 画面内容 | 应框选 |
|---|---|---|
| "蓝色皇冠道具" | 多人合照，其中一人头顶戴皇冠 | 仅皇冠道具的外接矩形，不含人脸/身体 |
| "耳环挂件" | 人物写真，耳部有挂件 | 仅耳环本身的紧凑外接矩形 |
| "菜品中的螃蟹" | 一桌菜的合影 | 仅螃蟹这一道菜/这一只螃蟹的区域 |

### 策略 B：`description` 为空/null —— 自动识别最显著主体

按常规"找主体"逻辑：识别画面中**面积最大、视觉最突出**的对象作为目标元素，通常是：
- 电商/产品图：居中的商品本体（不含背景留白）
- 菜品实拍图：主菜品整体（不含餐具外沿、背景桌面）
- 人像图：人物主体（不含大面积背景）

## 识别时请一并判断"目标是否完整"（供 v2 裁剪模型使用）

下游裁剪脚本（`crop_by_bbox.py`）会根据 bbox 是否贴/超出原图边界，自动判断目标是否已被
原图边缘截断，并据此选择"完整保留+padding"或"非对称裁剪"两种策略。识图时请注意：

- **正常框选即可，不需要主动收窄或外扩来"避开"边缘**：只要 bbox 真实反映目标的外接矩形，
  哪怕它贴着原图边缘，脚本会自动识别为"目标本身不完整"并做相应处理。
- **不要因为目标贴边就人为把 bbox 缩小到原图内部**——这样会让脚本误判为"目标完整"，
  从而错误地对一个本来就不完整的目标做居中裁剪，效果反而更差。
- 对细长/延伸型元素（眼镜腿、衣领、袖口、发梢、耳环挂坠链）要格外注意**把整条延伸部分都框进去**，
  这类元素是历史上"完整元素被裁掉"问题的高发区，宁可 bbox 稍大，不要偏小。
- 若难以判断精确边界，可采用"网格叠加辅助定位"：在心里/描述中把图片划分为若干等份网格，
  逐格核对目标边缘落在哪个网格线附近，再换算成 0~1 相对坐标，比直接目测估算更准。

## 批量提交建议（降低 token 开销）

- 尽量一次性把一批图片（如 5~15 张，视图片分辨率与上下文限制而定）连同各自的
  `name` + `description` 一起提交，要求在一次回复中输出这批图片对应的完整
  `bboxes.json` 数组，而不是逐图单独往返。
- 每批次输出后立即写入/追加到同一个 `bboxes.json` 文件，避免因中途失败丢失已识别结果。
- 若某一批中部分图片识别失败，仍应为该批次内所有图片输出条目（失败的用 `bbox: null`），
  保证 `bboxes.json` 与 `manifest.json` 条目数一致，便于下游脚本按 `name` 精确匹配。
