# 裁剪留白（padding）原理说明

> v2 更新：本 skill 已从"紧密度（tightness）插值"改为"留白（padding）+ 完整性硬约束"模型。
> 旧的 `--tightness` 参数已废弃（仍可传入但不再生效，仅打印警告），请统一使用 `--padding`。
>
> v3 更新：新增 `--fit` 策略参数，`contain`（默认）即本文档描述的"完整性硬约束"模型；
> `cover` 是与之互补的新增策略——裁剪框改为被完整包含在 padded_bbox 内的最大框，铺满
> 输出画布，允许裁掉目标边缘，绝不补白。本文档下文的决策树、越界补白、非对称裁剪等
> 规则均只适用于 `contain`；`cover` 模式恒不越界、恒不补白，逻辑更简单，详见
> `scripts/geometry.py` 中的 `compute_crop_box_cover()`。

## 为什么改掉 tightness

旧模型让裁剪框在 contain（完整包裹元素）与 cover（收缩裁边）之间线性插值，
`tightness` 越高越会主动裁掉元素的边缘——这与"目标元素必须完整保留"的核心要求是冲突的：
只要识别的 bbox 有 1~2% 的误差，配合较高的 tightness，就会把镜腿、衣领等细长/延伸部分切掉。

v2 的核心原则改为：

> **完整的目标元素永远不能被裁掉。** 裁剪框只能围绕目标"扩展/平移/兜底补白"，
> 不能反向"收缩进"目标内部。

## 直觉理解：padding 是什么

`--padding`（0~100，单位：**目标框最长边**的百分比）控制的是**目标元素周围留多少呼吸空间**，
而不是"裁不裁目标"：

- `padding=0`：裁剪框尽量贴合目标 bbox（仍保证完整包裹），几乎不留白。
- `padding=5`（默认）：以目标 bbox 的最长边 `L = max(宽, 高)` 为基准，
  `p = L × 5%`，在目标四周（上下左右）**统一扩展相同的像素值 `p`**——
  而不是宽方向按宽度算、高方向按高度算。这样细长目标（比如一条项链）
  短边方向不会因为"按自身高度算"而留白偏小。
- `padding` 越大，目标周围环境信息越多，目标在成品中占比越小。
- **不支持负数**：负 padding 等价于重新引入"主动裁边"，与核心约束矛盾，脚本会直接报错拒绝。
- **padding 是必须保留的安全区，不会为了凑原图空间而自动减少**（仅在目标本身已被
  原图边缘截断时例外，见第 4 步情况 B）：只要目标完整，哪怕原图放不下，也会保留
  完整 padding 并改为补白，而不是牺牲 padding 去贴合原图边界。

## 计算流程（决策树）

给定原图尺寸 `(img_w, img_h)`、目标 bbox（像素坐标）、目标比例 `r = 目标宽/目标高`、
`padding_pct`，`scripts/crop_by_bbox.py` 中的 `compute_crop_box()` 按以下顺序决策：

### 第 0 步：判断目标是否已被原图边缘截断

检查 bbox 四条边是否贴/超出原图边界（容差约为对应边长的 1%）。若某一边贴边，
认为目标在**这一侧**本身就不完整（例如盘子已经被原图左边缘切掉一部分），
该侧不会再叠加 padding（贴边处没有"周围环境"可留）。

### 第 1 步：按 padding 扩展 bbox，尝试构造 contain 裁剪框

以目标 bbox 最长边 `L` 为基准算出 `p = L × padding_pct`，对非贴边的方向统一扩展 `p`，
得到 `padded_bbox`；以 `padded_bbox` 为基准构造满足比例 `r` 且完整包含它的最小裁剪框
（contain 尺寸：宽高比更"宽"则贴宽边，更"高"则贴高边）。

### 第 2 步：裁剪框能放进原图吗？——优先整体平移（shift-to-fit）

若 `padded_bbox` 本身位于原图内，且对应裁剪框宽高都不超过原图尺寸，说明只是位置问题：
整体平移裁剪框（不缩放、不形变），在保证仍完整包含 `padded_bbox` 的前提下移入原图。
若完整目标靠近边缘，导致请求的 `padded_bbox` 已超出原图，即使裁剪框尺寸不大也不能靠
平移凭空恢复该侧安全区，此时直接进入第 4 步情况 A，以补白保留完整 padding。

### 第 3 步（仅目标本身已被截断时）：逐步降低非贴边侧 padding

**若目标本身完整（未贴边）**：不会走这一步——padding 是必须保留的安全区，
平移仍放不下时直接进入第 4 步情况 A（补白），不会自动减少 padding。

**若目标本身已被截断（贴边）**：贴边侧本来就没有留白诉求，非贴边侧的留白按
`padding, padding/2, padding/4, 0` 依次尝试，只要某个值下裁剪框能放进原图，立即采用。

### 第 4 步：仍放不下——区分两种收尾方式

**情况 A：目标本身完整（未贴边）——真正的比例冲突（ratio_conflict）**

原图尺寸无法在保持指定比例、且保留完整 padding 的前提下容纳目标（例如目标很宽、
原图偏矮的场景，如 `1800×900` 的完整目标出现在 `1920×1080` 的原图里，要求输出 `1:1`）。
此时按用户确认的优先级：**目标完整 + 完整 padding > 严格贴合原图边界**，保留
第 1 步算出的完整 `padded_bbox` 对应裁剪框，居中放置，允许裁剪框超出原图范围，
超出部分用背景色（`--bg-color`，默认白色）做**最小必要的补白**——不裁目标，也不
牺牲 padding。这是本模型中**唯一**允许产生留白/补白画布的场景，且只在数学上无法
回避时才触发。

**情况 B：目标本身已被截断（贴边）——边界受限的非对称裁剪**

目标本来就不完整（原图本身没拍全），不做补白去"恢复"缺失部分，也不强求几何居中：
以可见部分的中心为构图锚点，裁剪框尽量在原图内部按等比缩小到能放下的最大尺寸
（不越界、不补白），标记为建议人工复核。

## 阶段2几何校验与分级

`scripts/render_bbox_preview.py` 在正式裁剪前绘制目标 bbox、padding bbox 和最终裁剪框，
并生成联系表与 JSON 报告。`crop_by_bbox.py` 在保存成品前后独立检查：

- 裁剪框比例是否与目标比例一致；
- 完整目标及其 padding 安全区是否被裁剪框完整包含；
- 截断目标的裁剪框是否保持在原图内；
- 越界是否正确标记为补白；
- 成品文件能否重新打开、尺寸是否符合目标值；
- bbox 是否命中目标过小、接近整图、极端宽高比等识别风险。

最终每张图只有一个 grade：`ok`、`needs_review`、`unrecognized` 或 `failed`。
`needs_review` 的成品仍在主目录，同时复制到同名子目录供集中核对；几何硬错误不会继续保存成品。

## 输出缩放与画质

裁剪区域会按目标比例缩放到 `--long-side` 指定尺寸（`PIL.Image.resize` + `LANCZOS`）。
当输出尺寸小于裁剪区域时是下采样；当输出尺寸大于裁剪区域时会发生普通插值放大，可能变软，
但不会调用超分模型。若要避免放大导致的清晰度下降，应让原图和裁剪区域分辨率足够。

## 与旧版 tightness 的映射关系

旧版 `tightness` 与新版语义并非线性对应，不建议做数值换算，直接改用 `padding` 即可：

| 旧参数 | 旧效果 | 新模型下的等价做法 |
|---|---|---|
| `tightness=0` | contain，完整保留，可能留白 | `padding` 设为你想要的留白量（如 5~10） |
| `tightness=100` | cover，主动裁边 | 改用 `--fit cover`（v3 新增，语义与旧版 tightness=100 类似，但边界处理更明确） |
| `tightness=50` | 折中，仍可能裁边 | 不再有直接等价，建议用 `padding=0` 或小的 `padding` |

## 市面参考

- CSS `object-fit: contain`（完整显示，可能留白）——新模型的默认行为与之接近，
  区别在于新模型会主动平移裁剪框；完整目标不缩减请求的 padding，只有源目标本身已截断时
  才允许降低非贴边侧 padding。
- 开源项目 `ai-image-cropper-v2` 采用的核心概念正是 `padding`（检测目标周围增加呼吸空间），
  本 skill 直接复用该命名，不再引入 `margin`/`tightness` 等多套易混淆的概念。

具体实现见 `scripts/crop_by_bbox.py` 中的 `compute_crop_box()` / `shift_to_fit()` /
`crop_with_canvas()` 函数。
