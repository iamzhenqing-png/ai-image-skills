# 批量生成并视觉归一化

## 用途

接收本地图片目录或物品文本清单，以及用户已确认的完整 Prompt；先批量生成 PNG，再将主体视觉大小统一到用户指定的画布安全区内，未指定时才使用 800×800。适用于需要保留生成图完整画面和原有背景、同时让整批主体尺度一致的素材生产场景。

## 输入

| 参数 | 必填 | 默认值 | 说明 |
|---|---|---|---|
| 图片目录或物品清单 | ✅ 二选一 | 无 | 图片目录用于图生图/风格迁移；物品清单用于文生图。 |
| 完整 Prompt | ✅ 必填 | 无 | 原样传给批量生成 skill；不得自动读取、补写、拼接或改写。 |
| 工作目录 | ✅ 必填 | 无 | 运行态产物根目录；各步骤在其下建立独立 `stepN-<语义>/` 目录。 |
| 共享参考图路径 | 可选 | 无 | 传入后作为全批次共用参考图。 |
| Provider / 模型 | 可选 | 使用批量生成 skill 当前配置解析结果 | 由批量生成 skill 的对外契约决定可用组合。 |
| 远端生成质量 | 可选 | `2K` | 传入批量生成 skill 的远端质量提示。 |
| Step 1 最终 PNG 尺寸 | 可选 | 保留远端生成尺寸 | **仅映射给 Step 1 的 `batch-image-generation --size`**；不得作为 Step 2 画布尺寸。 |
| 输出画布尺寸 | 可选 | `800x800` | **本轮 Step 2 成品画布的唯一来源**；必须原样映射给 `visual-scale-normalizer plan --canvas-size`。用户显式提供时优先于默认值。 |
| 安全边距 | 可选 | `64` | Step 2 四边安全边距，单位为像素。 |
| 目标占比 | 可选 | `0.82` | Step 2 的 `target-fill` 首轮起点；必须经过预演复核。 |
| 过渡陡峭度 | 可选 | `0.9` | Step 2 的 `transition-steepness` 首轮起点；必须经过预演复核。 |
| 最大放大倍率 | 可选 | `1.0` | Step 2 的 `max-upscale`；`1.0` 表示不放大原图。 |
| 生成图背景预期 | 可选 | 不含真实透明背景 | 仅用于预估 AI 外框工作量；以 `prepare` 的 manifest 结果为准。 |

> Step 2 的四项数值是本工作流确认的首轮参数，不是原子 skill 的通用预设。任何一轮都必须以 `report.json` 和 `contact-sheet.png` 的复核结果决定是否调整。

### 缺参数时怎么办（四条铁律，不许简化）

1. **一次性抛出完整参数模板**给用户填。必填项标`❓ 待填写`，可选项直接填真实默认值。
   **禁止**一项一项追着问，那样要来回好几轮，用户会烦。

   模板长这样：
   ```
   请把下面几项补全后发回给我：

   图片目录或物品清单：❓ 待填写（两者二选一）
   完整 Prompt：❓ 待填写
   工作目录：❓ 待填写
   共享参考图路径：无
   Provider / 模型：使用当前配置
   远端生成质量：2K
   Step 1 最终 PNG 尺寸：保留远端生成尺寸
   输出画布尺寸：800x800
   安全边距：64
   目标占比：0.82
   过渡陡峭度：0.9
   最大放大倍率：1.0
   生成图背景预期：不含真实透明背景
   ```

2. **必填项永远不许用默认值**，也不许猜。只有可选项才能套默认值。
3. 用户回复后，逐项检查。只要有必填项**仍为空、仍是 `❓ 待填写`、或明显无效**（路径不存在、文件类型不对），**立即停止，不许执行**。再次明确指出缺哪几项，**不许编造一个值继续跑**。
4. 全部齐了之后，**开工前回显一次完整摘要**再动手：
   ```
   即将开始：
   - 素材：<图片目录或物品清单>，共 N 个条目
   - 完整 Prompt：已提供（不回显敏感信息）
   - 共享参考图：<路径或无>
   - 工作目录：<目录>
   - 步骤产出：step1-generated/ → step2-normalized/
   - Step 1 最终 PNG 尺寸：<用户值或“保留远端生成尺寸”>
   - Step 2 输出画布尺寸：<输出画布尺寸>（将传给 `plan --canvas-size`）
   - 安全边距：<安全边距>
   - target-fill：<目标占比>
   - transition-steepness：<过渡陡峭度>
   - max-upscale：<最大放大倍率>
   确认无误我就开始。
   ```
   > 摘要中的值为本轮冻结值。用户确认后，不得被示例值、默认值、Step 1 尺寸或旧 `report.json` 覆盖。

## Step 0 环境体检

动手之前先逐项检查，任何一项不通过就停下来报告，**不要**边跑边报错：

1. 「前置 skill 清单」里的每一个 skill，目录是否都存在。
2. 每个前置 skill 的 `SKILL.md` 是否都能读到，并现读它的「对外契约」（**不要**凭记忆写命令）。
3. Python 3 与两个原子 skill 声明的 Python 依赖是否已安装；确认批量生成 skill 的 Provider 配置和所选模型可用。
4. 用批量生成 skill 的 `--dry-run` 完成任务路由、条目数、输出目录和 Prompt 预览自检；该预演不得发起 API 请求。
5. 图片目录或物品清单、可选参考图是否存在且类型正确；图片目录/清单中是否真有可处理条目。
6. 工作目录能否创建/写入，并能在其下创建 `step1-generated/` 与 `step2-normalized/`。

## 守则

1. **不写死命令。** 每一步现读对应原子 skill 的 `SKILL.md`，照它的「对外契约」组装命令。本工作流层**不直接**操作原子 skill 职责内的文件或 API。
2. **单条失败不中断整批。** 某一个素材处理失败，记一条、继续下一个，最后统一汇总「成功 N / 失败 M / 失败清单」。只有整体性故障才停：Provider 配置失效、依赖缺失、Step 0 不通过、源目录不存在。
3. **硬停点必须显式标注，不许自行跳过。** 本流程的硬停点：① Step 1 的 `--dry-run` 完成后，核对路由、数量、输出目录与 Prompt 预览，等待用户确认后才允许真实生成；② Step 2 的 `prepare` 后，生成 AI 外框后必须展示每个 `needs_ai_bbox: true` 条目的外框坐标并等待用户明确确认；仅收到确认后才允许传入 `--confirm-ai-bboxes` 执行 `plan`；③ Step 2 的 `plan` 后，人工查看 `report.json` 与 `contact-sheet.png`，并核对 `report.json.canvas_size` 与本轮冻结的输出画布尺寸完全一致；仅收到确认后才允许传入 `--confirm-report` 执行 `execute`。不得使用 `run --no-review` 或任何跳过复核的连续执行方式。
4. **产物走文件系统目录**，不引入数据库。不在 skill 目录内产生任何运行态文件（缓存、日志、中间产物一律放到工作目录下对应的 `stepN-<语义>/` 中）。
5. **透传参数最小化。** 只给下游原子 skill 它真正需要的参数，不告诉它自己在哪条流里、是第几步。
6. **路径一律相对本 skill 目录**，不写死绝对路径。需要在 home 下存持久化数据时用 `~`。

## 前置 skill 清单

本流程依赖以下原子 skill，缺任意一个都不能开工（格式固定，台账刷新脚本要靠它反向聚合，**不要改标题、不要去掉反引号**）：

- `batch-image-generation` — 按用户确认的完整 Prompt 批量生成 PNG。
- `visual-scale-normalizer` — 统一生成图中主体的视觉大小并输出标准画布成品。

## Step 1 批量生成 PNG

- 用哪个 skill：`batch-image-generation`
- 输入：图片目录或物品清单、完整 Prompt，以及可选共享参考图、Provider、模型、远端质量与最终 PNG 尺寸。
- 产出目录：`<工作目录>/step1-generated/`（通过该 skill 的正规 `--output`/`-o` 参数显式传入，不使用默认输出目录）。
- 要拿到什么产出：与输入条目一一对应的 PNG；目录输入保留相对路径和文件名，清单输入按三位序号命名。记录成功数、失败数与失败原因。
- 做法：现读该 skill 的「对外契约」，先按真实参数完成 `--dry-run`；在硬停点核对预览后，才按同一组已确认输入真实生成。
- 注意：重复真实运行会覆盖同路径输出、重新请求 Provider，并可能再次产生费用；不要将未确认的旧产物当作本轮结果。

## Step 2 视觉归一化

- 用哪个 skill：`visual-scale-normalizer`
- 输入：`<工作目录>/step1-generated/`。
- 产出目录：`<工作目录>/step2-normalized/`（通过该 skill 的正规 `--output-dir` 参数显式传入，不使用默认输出目录）。
- 要拿到什么产出：`manifest.json`、`ai_bboxes.json`（如需要）、`report.json`、`contact-sheet.png`、三级质检目录与 `final-report.json`。
- 做法：按交互式 `prepare → AI 外框审核 → plan → 预演审核 → execute` 执行。参数映射必须唯一且显式：`<输出画布尺寸>` → `plan --canvas-size`；`<安全边距>` → `plan --margin`；`<目标占比>` → `plan --target-fill`；`<过渡陡峭度>` → `plan --transition-steepness`；`<最大放大倍率>` → `plan --max-upscale`。Step 1 的 `--size` 不得替代、推导或影响 `plan --canvas-size`。
- AI 外框：本流程预期 Step 1 生成图没有真实透明背景。`prepare` 后以 manifest 为唯一依据；对每个 `needs_ai_bbox: true` 条目直接读原图，按该 skill 的 `bbox-detection-guide.md` 生成相对坐标。识别不可靠时写 `null`，不得猜测主体位置。写入 `ai_bboxes.json` 后必须回显全部外框，明确询问用户是否确认；未收到确认不得执行 `plan`，收到确认后才传 `--confirm-ai-bboxes`。
- 人工复核：`plan` 后停下检查 `report.json` 与 `contact-sheet.png`。先核验 `report.json.canvas_size` 必须等于本轮冻结的 `<输出画布尺寸>`；不一致、缺失或无法确认时，使用冻结参数重跑 `plan`，不得 `execute`。若主体识别、裁切、画质限制或安全边距不符合预期，调整显式策略参数后重跑 `plan`；仅在用户确认后传入 `--confirm-report` 执行 `execute`。

## Step 3 交付与汇总

- 最终成品：`<工作目录>/step2-normalized/completed-成功生成的成品/` 内的 PNG。
- 需复查项：`attention-需要检查的图片/`；失败项：`failed-处理失败的文件/`。两者不得混入最终成品交付目录。
- 汇总报告：结合 Step 1 批次结果与 Step 2 的 `final-report.json`，报告成功 N / 失败 M / 失败清单及原因，并说明待复查文件数量。
