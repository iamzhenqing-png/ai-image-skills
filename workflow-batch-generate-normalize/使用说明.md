# 批量生成并视觉归一化 · 使用说明

这条工作流会把一批图片或物品名称，先生成 PNG，再把每张图的主体调整到相同的视觉大小，最后输出指定画布尺寸的成品 PNG；未指定时默认是 800×800。

## 它适合什么场景

适合需要整批生成同风格素材、但又希望每张图里的主体看起来差不多大的场景，例如商品图、活动素材或贴纸素材。

它不会抠图或清背景：生成图原本的画面和背景会随着整张图片一起缩放。

## 开始前准备

一次准备以下内容：

1. **图片目录或物品清单（二选一）**
   - 图片目录：用于图生图或风格迁移；文件名要能说明物品是什么。
   - 物品清单：一个 UTF-8 文本文件，每行一个物品名称，用于文生图。
2. **完整 Prompt**：必须是已经确认好的最终指令。工作流不会替你改写或补全。
3. **工作目录**：专门放本次运行的中间产物和成品。
4. **输出画布尺寸（可选）**：Step 2 最终成品尺寸，例如 `800x800`；未提供时默认 `800x800`。
5. **可选共享参考图**：整批要参考同一种风格时提供。
6. **Provider 配置**：按 `batch-image-generation` 的说明，在本地完成配置。

## 默认成品设置

本流程默认使用以下首轮设置：

| 项目 | 默认值 |
|---|---|
| 成品画布 | `800x800` |
| 安全边距 | 四边各 `64` 像素 |
| 主体目标占比 | `0.82` |
| 过渡陡峭度 | `0.9` |
| 最大放大倍率 | `1.0`（不放大原图） |
| 生成图背景预期 | 不含真实透明背景 |

这些是本流程的首轮起点，不是所有素材都适用的通用预设；其中成品画布可由本轮的“输出画布尺寸”覆盖。正式输出前必须查看预演报告，再决定是否调参数。

## 执行时会发生什么

```text
图片目录 / 物品清单 + 完整 Prompt
              ↓
step1-generated/       批量生成 PNG
              ↓
step2-normalized/      扫描主体、预演、确认后合成
              ↓
completed-成功生成的成品/  最终 PNG
```

工作流会建立这两个独立目录，不会覆盖原始输入：

```text
你的工作目录/
├── step1-generated/                 ← Step 1 生成图
└── step2-normalized/                ← Step 2 的全部报告与成品
    ├── report.json                  ← 数字预演报告
    ├── contact-sheet.png            ← 预演联系表
    ├── completed-成功生成的成品/     ← 可交付 PNG
    ├── attention-需要检查的图片/     ← 画质受限等待复查项
    └── failed-处理失败的文件/        ← 失败项
```

## 三个必须停下确认的地方

1. **生成前预览**：先查看任务路由、条目数量、输出位置和每项 Prompt 预览；确认后才会真实调用生图服务。
2. **主体外框识别后**：没有真实透明背景的图，需要按主体实际位置补充 AI 外框。工作流会展示 `ai_bboxes.json` 中每张图的外框并等待你的明确确认；未确认不能进入预演。
3. **视觉归一化预演后**：查看 `report.json` 和 `contact-sheet.png`，并确认 `report.json.canvas_size` 与要求的成品尺寸一致。如果主体偏小、被裁切或放大后画质不理想，先调参数再生成最终成品。

## 去哪里拿成品

只交付下面这个目录中的文件：

```text
<工作目录>/step2-normalized/completed-成功生成的成品/
```

`attention-需要检查的图片/` 和 `failed-处理失败的文件/` 分别是待复查和失败项，不能混进最终交付。

## 注意事项

- 一次真实生图会使用 Provider 额度；重复运行同一路径会重新请求并覆盖生成图。
- 生成前一定要提供完整 Prompt；系统不会自动读取模板或猜测描述。
- 这条工作流依赖 `batch-image-generation` 和 `visual-scale-normalizer` 两个 skill。分发给同事时必须连同它们一起提供。
