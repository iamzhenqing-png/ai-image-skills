# 仓库与分发说明

## 仓库怎么摆

唯一真源是独立 Git 仓库：

```text
~/dev/ai-image-skills/
```

CodeBuddy 等平台的用户级 skills 目录只放逐个 skill 的软链接，例如：

```text
~/.codebuddy/skills/bg-remover -> ~/dev/ai-image-skills/bg-remover
```

平台按 `skills/*/SKILL.md` 的一层结构发现 skill，因此不能只建立一个指向整个仓库的总链接。
`scripts/link.sh` 会自动遍历仓库第一层的 `*/SKILL.md`，无需维护手写清单。

第三方 skill 继续保留在各平台的 skills 目录中，完全位于本仓库的 Git 视野之外。
仓库根 `.gitignore` 只负责排除密钥、私人台账、缓存和运行产物，不再使用白名单。

## 首次安装

```bash
mkdir -p ~/dev
git clone https://github.com/iamzhenqing-png/ai-image-skills.git ~/dev/ai-image-skills
cd ~/dev/ai-image-skills
chmod +x scripts/*.sh .githooks/*
git config core.hooksPath .githooks
./scripts/link.sh
```

`link.sh` 支持 `~/.agents/skills`、`~/.codebuddy/skills`、`~/.claude/skills`：存在即处理。
若同名目标是实体目录，先移到 skills 目录内隐藏的 `.ai-image-skills-backups/` 留档，再建立链接；
若链接指向其他位置，则报告并跳过，不会覆盖。

## 新增或收纳 skill

新建 skill 时直接指定仓库路径：

```bash
python3 "/Applications/CodeBuddy CN.app/Contents/Resources/app/extensions/genie/out/extension/builtin/skill-creator/scripts/init_skill.py" <skill-name> --path "$HOME/dev/ai-image-skills"
./scripts/link.sh
```

上述 `init_skill.py` 路径仅适用于当前 macOS CodeBuddy CN 安装位置；应用升级后应先重新确认。

如果 skill 已经作为实体目录存在于某个平台的 skills 目录中，运行：

```bash
./scripts/adopt.sh <skill-name>
```

`adopt.sh` 会校验第一层 `SKILL.md`、复制进仓库、保留原目录备份，再刷新链接。
仓库已存在同名 skill 或多个平台存在同名实体目录时会停止，要求人工比对。

## 旧的 5 个单独仓库

`bg-remover`、`batch-image-resize`、`batch-style-transfer`、`image-element-crop`、`head-shoulder-crop`
原先各自是一个 GitHub 仓库。旧远端保留历史但停止更新；本地旧 `.git` 目录仅作为历史归档，
不属于当前套装仓，也不应放回任何 skill 目录。

## 分发给同事

让同事按“首次安装”执行即可。必须整套分发，不要挑选部分原子 skill；skill 系统不会自动安装依赖。
安装完成后重启 CodeBuddy。

## commit 纪律

| 前缀 | 含义 | 要做的事 |
|---|---|---|
| `feat(<skill>):` | 加功能，对外契约没变 | 直接提交 |
| `fix(<skill>):` | 修 bug，对外契约没变 | 直接提交 |
| `contract(<skill>)!:` | **对外契约变了** | 改契约 + 改 `CHANGELOG.md` + 改所有受影响工作流，三样同一次 commit |

改契约前先查 `_registry/工作流台账.md` 表二，看这个 skill 被哪些工作流依赖。

## 每次改完 skill 的收尾动作

```bash
python3 _registry/scripts/refresh_registry.py --write
./scripts/link.sh
```

台账含私人信息，由根 `.gitignore` 排除，只留在本地。
