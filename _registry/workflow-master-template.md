# workflow 母版

本文件是「新增一条工作流」时的模板与规矩。一条工作流 = 一个独立 skill。
本文件**不是 skill**，没有 frontmatter，不会被自动加载，也不参与分发给同事。

阅读方式：
- 第一块【创作约定】= 给建工作流的人看的规矩，**不要**复制进新 skill。
- 第二块【可复制正文】= 整块复制进新 skill 的 `SKILL.md`，然后把所有 `【】` 占位符填掉。

---

# 第一块【创作约定】（不复制进SKILL.md）

## 一条工作流就是一个独立 skill

目录结构（扁平，**不要**再套 `workflows/` 子目录）：

```
workflow-<英文名>/
├── SKILL.md          ← 执行步骤（给 AI 看）
├── 使用说明.md← 大白话操作说明（给同事看）
└── references/       ← 可选：prompt 模板、参数表等
```

## 层级职责（最重要的一条，越界就白做了）

| 层 | 只做什么 | 绝对不做什么 |
|---|---|---|
| **工作流层**（本层） | 声明「第 N 步进哪个原子 skill、要拿到什么产出」 | **不写具体命令**、不直接操作图片/调API/读写原子 skill 职责内的文件 |
| **原子 skill 层** | 干实活 | 不知道自己被谁调用，也不该知道 |

工作流层写命令 = 原子 skill 一升级，所有工作流全部失效。
正确做法：**运行时现读**原子 skill 的 `SKILL.md`，照它当时的「对外契约」组装命令。

## 开工前必做

1. 打开 `_registry/工作流台账.md` 的**表一**，确认这条流不存在、也没有和现有流重叠。
2. 把要用到的原子 skill 的「对外契约」逐个读一遍，确认输入输出能接得上。缺原子能力就先去建原子 skill（见 `atomic-master-template.md`）。

## 命名规则

- 目录名 = frontmatter 的 `name`，必须以 `workflow-` 开头，且只能是小写字母、数字、连字符（`^[a-z0-9-]+$`）。
  **不能带中文**，所以中文名放到 `description` 开头，用【】括起来。
- 例：`name: workflow-sticker-batch`，`description: 【幸运物贴纸化】此工作流……`

## 工作目录与步骤产出命名

- 每条工作流在用户指定的工作目录下，为每个步骤建立独立产出目录：`stepN-<语义>/`。
  例如：`step1-generated/`、`step2-normalized/`。
- 每一步都必须通过原子 skill 的正规输出参数**显式指定**自己的 `stepN-<语义>/` 目录，**不得依赖**原子 skill 的默认输出目录。
- 下一步只读取上一步对应的产出目录；例如 Step 2 读取 `step1-generated/`，并输出到 `step2-normalized/`。
  这样能保留所有上游产物，不覆盖原图或中间产物，也避免不同原子 skill 的默认目录规则造成嵌套或读写歧义。
- `<语义>` 使用小写英文和连字符，准确描述该步骤产物；不要使用含混的 `output`、`result`。

## 降低误触发

在 `description` 里加一句约束：

> 仅当用户明确要求执行【中文流程名】工作流时使用。

⚠️ 如实说明：**是否存在「禁止自动触发、只允许 `@` 显式调用」的开关，没有查到确切文档，不知道。**
上面这句约束句能明显降低误触发，但不保证 100%。不要把它当成保险。

## 母版内容必须内联复制

「输入」「Step 0」「守则」这几节的内容，**整段复制**进每个工作流的 `SKILL.md`。
不要写成「详见 `_registry/workflow-master-template.md`」—— 分发给同事时 `_registry/` 可能没跟着过去，一引用就断链。
重复几百字是可以接受的代价，断链不可接受。

## 建完之后必做

1. 写 `使用说明.md`（大白话版，给非技术同事看）。现成范本：`lucky-item-style-transfer/使用说明.md`。
2. 核对「前置 skill 清单」是否写全—— 这份清单**同时**用于运行时 Step 0 自检、和分发打包时清点依赖，漏一个同事就会跑到一半失败。
3. 刷新台账：
   ```bash
   python3 _registry/scripts/refresh_registry.py --write
   ```
4. 拿一批真实素材整条流跑通一次，再交给同事。
5. 如果提供了 `.command` 之类的双击脚本，在`使用说明.md` 里写明「**macOS 专属**」，
   并给出终端里的等价命令。（团队目前全是 macOS，允许用 `.command`；但不许写死个人绝对路径。）

## 分发

分发 =把**全套**（工作流 + 它依赖的全部原子 skill）一起给。
skill 系统**没有**依赖自动安装机制，让同事自己挑要装哪几个原子 skill，必挑漏、必断链。

## commit 前缀约定

| 前缀 | 含义 | 要做的事 |
|---|---|---|
| `feat(<name>):` | 加功能，对外契约没变 | 直接提交 |
| `fix(<name>):` | 修 bug，对外契约没变 | 直接提交 |
| `contract(<name>)!:` | **对外契约变了** | 必须同时改 `CHANGELOG.md` + 所有受影响的工作流，**三样放同一次 commit** |

# 第二块【可复制正文】（整块复制进 SKILL.md，填掉所有【】）

> 下面这一大块（从 `---` 开头的 frontmatter 到最后一行）整块复制。
> 最外层的四个反引号只是包装，复制时不要带上。

````markdown
---
name: workflow-【英文名】
description: 【中文流程名】此工作流用于【一句话说明从什么素材做出什么成品】。仅当用户明确要求执行【中文流程名】工作流时使用。
---

# 【中文流程名】

## 用途

【两三句话说明：给它什么原始素材 → 最后交付什么成品 → 典型用在什么场景。】

## 输入

| 参数 | 必填 | 默认值 | 说明 |
|---|---|---|---|
| 【素材目录】 | ✅ 必填 | 无 | 【说明】 |
| 【参考图路径】 | ✅ 必填 | 无 | 【说明】 |
| 【工作目录】 | 可选 | 【真实默认值】 | 运行态产物的根目录；各步骤在其下使用 `stepN-<语义>/` 子目录。 |
| 【尺寸】 | 可选 | 【真实默认值】 | 【说明】 |

### 缺参数时怎么办（四条铁律，不许简化）

1. **一次性抛出完整参数模板**给用户填。必填项标`❓ 待填写`，可选项直接填真实默认值。
   **禁止**一项一项追着问，那样要来回好几轮，用户会烦。

   模板长这样：
   ```
   请把下面几项补全后发回给我：

   素材目录：❓ 待填写
   参考图路径：❓ 待填写
   工作目录：【真实默认值】
   尺寸：【真实默认值】
   ```

2. **必填项永远不许用默认值**，也不许猜。只有可选项才能套默认值。

3. 用户回复后，逐项检查。只要有必填项**仍为空、仍是 `❓ 待填写`、或明显无效**（路径不存在、文件类型不对），
   **立即停止，不许执行**。再次明确指出缺哪几项，**不许编造一个值继续跑**。

4. 全部齐了之后，**开工前回显一次完整摘要**再动手：
   ```
   即将开始：
   - 素材：<目录>，共 N 个文件
   - 参考图：<路径>
   - 工作目录：<目录>
   - 步骤产出：step1-<语义>/ → step2-<语义>/ → ...
   - 关键参数：<...>
   确认无误我就开始。
   ```

## Step 0 环境体检

动手之前先逐项检查，任何一项不通过就停下来报告，**不要**边跑边报错：

1. 「前置 skill 清单」里的每一个 skill，目录是否都存在。
2. 每个前置 skill 的 `SKILL.md` 是否都能读到，并现读它的「对外契约」（**不要**凭记忆写命令）。
3. 依赖是否装好【列出要检查的 pip 包 / 命令 / 模型文件】。
4. 【若依赖 API Key：Key 是否已配置、连通性自检怎么跑】
5. 输入目录是否存在、里面是否真有可处理的文件。
6. 工作目录能否创建/写入，并能在其下创建每一步的 `stepN-<语义>/` 产出目录。

## 守则

1. **不写死命令。** 每一步现读对应原子 skill 的 `SKILL.md`，照它的「对外契约」组装命令。
   本工作流层**不直接**操作原子 skill 职责内的文件或 API。
2. **单条失败不中断整批。** 某一个素材处理失败，记一条、继续下一个，最后统一汇总「成功 N / 失败 M / 失败清单」。
   只有整体性故障才停：API Key 失效、依赖缺失、Step 0 不通过、源目录不存在。
3. **硬停点必须显式标注，不许自行跳过。** 本流程的硬停点：【逐条列出；没有就写「无」】
4. **产物走文件系统目录**，不引入数据库。不在 skill 目录内产生任何运行态文件（缓存、日志、中间产物一律放到工作目录下对应的 `stepN-<语义>/` 中）。
5. **透传参数最小化。** 只给下游原子 skill 它真正需要的参数，不告诉它自己在哪条流里、是第几步。
6. **路径一律相对本 skill 目录**，不写死绝对路径。需要在 home 下存持久化数据时用 `~`。

本流程依赖以下原子 skill，缺任意一个都不能开工（格式固定，台账刷新脚本要靠它反向聚合，**不要改标题、不要去掉反引号**）：

- `【原子skill名】` — 【在本流程里负责什么】
- `【原子skill名】` — 【在本流程里负责什么】

- 产出目录：`<工作目录>/step2-【语义】/`（通过该 skill 的正规输出参数显式传入，不使用默认输出目录）
````
